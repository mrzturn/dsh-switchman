## なぜ必要か

DSH で作業を続けていると、時間がたつうちに次の 2 つにぶつかります：

1. **会話がどんどん重くなる。** 履歴でコンテキストが数十万 token まで膨らむと、モデルは物忘れが増え、遅くなり、高くつきます。最後には手動 /compact 一択になりますが、圧縮するたびに細部がこぼれ落ちます。
2. **主力モデルが何もかも自分でこなす。** ファイルを 1 つ調べる、テストを回す、データを照合する——そのすべてを主力モデルが齧っています。遅い上にお金もかかり、その大半は実は安いモデルに任せられるはずの仕事です。

dsh-switchman は [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）のプラグインです。導入すると、メインモデルは「何もかも自分でこなす」役からディスパッチャーへ変わります：水位を測り、レーンを選び、タスクを配り、検収を見届ける。新しいモデルではなく、DSH に載せるオーケストレーション規律と設定画面ひと組です。具体的には 6 つのことをします：

**1. コンテキスト水位：長いセッションを溢れさせない。** 毎ラウンド、セッションの token 数をリアルタイムに集計し、3 本の水位線で段階的に引き締めます：50k（soft、変更可）で「そろそろ委譲すべき」と促し、90k（hard）で 1 回あたりのファイル読み取り予算を絞って締めくくりへ誘導し、130k（force）で自動ハンドオーバー——セッションを fork して記録を残し、コンテキストを圧縮し、続きを担うセッションを起こします。タスクは途切れません。ハンドオーバーの瞬間にまだ走っているバックグラウンドのサブエージェントも失われません：id・タスク説明・レポートのパスはすべて引き継ぎ文書に書き込まれ、続行するセッションはレポートをどこから回収するかを知っていて、同じ仕事を二重に振りません。配られた各サブエージェントには独立したハード上限が付き、上限に達したら HANDOFF 要約を書いて退場します。

**2. 6 つのディスパッチプール：仕事に見合うモデルを選ぶ。** 軽量プール（economy、小口の大量タスク）、機械的プール（mechanical、テンプレート的な書き換え）、主力プール（main、日常のコーディング）、高難度プール（hard、難推論と大規模リファクタリング）、マルチモーダルプール（vision、画像の読み取り）、レビュープール（review、独立した検証）。設定ページで候補にチェックを入れ、優先順位を付け（S/A/B/C ティアのアンカーは任意）、ルートごとに思考強度をピン留めできます——強度のドロップダウンは各モデルが実際に対応しているレベルから直接来るもので、汎用の 3 段階ではありません。メインモデルのプロンプトには毎ラウンド `[SWITCHMAN:POOLS]` 推奨表が添えられ、表に従って仕事を振ります。実行モードは 3 態：オフ / アドバイス / 強制（強制 = プール外モデルは即座に拒否）。

**3. Agent Teams モード：単独作業からチーム運用へ。** デフォルトはオフで、導入直後は軽量な subagent ディスパッチです。設定ページには独立した 2 つのスイッチがあります：

- **エージェントチームモード**——オンにするとチーム規律（デフォルト委譲 + 段階的検証 + 共有タスクボードの規律）が注入され、DSH の Agent Teams が自動で有効になります：メインモデルは常駐チームメイトを招集し（`spawn_teammate`）、共有タスクボードに仕事を積み（`team_task_*`）、チームメイトとメッセージをやり取り（`send_message`）できます。チームを組むべきタイミングには明確な規律があります：並行して進められる独立サブタスク、量が多く自己完結した仕事、メインコンテキストの水位がすでに高いとき、役割の分離が必要なとき。単発の一点調査は引き続き subagent へ。DSH の出荷時ポリシーは「ユーザーが名指ししなければチームを作らない」ですが、ここでは「使うべきときに使う」へ反転します。スイッチをもう一度オフにすれば、チーム関連の条項は残さず消え、実行中のセッションからチームツールを引き剥がすこともありません。
- **サブエージェントモデル許可リストの同期**——DSH には「Agent によるサブエージェントのモデル選択を許可」という承認リストがあります：プールで選んでも承認されていないルートを、メインモデルが名指しでディスパッチすると拒否されます（チームモードでは、推奨表と設定ページがそのようなルートに ⚠ を付けます）。このスイッチをオンにすると、6 プールの和集合がまるごとそのリストに書き込まれます——二重設定は不要になり、switchman が唯一の事実源となり、fork ディスパッチ経路もまとめて取り込まれます。許可リストは「新規セッション」時点のスナップショットで効くため、同期はそれ以降に開いたセッションにのみ反映されます。

セッションヘッダーには分かりやすい表示が出ます：⚡「自律チーム」バッジ、◇ 現在のセッションで実際に使われているモデル。自動ハンドオーバーが進行している間は「ハンドオーバー進行中 · セッションをバックアップ / コンテキストを圧縮 / 起こして継続」というリアルタイム表示が現れます。

**4. 言語設定：一度尋ねて、ずっと覚える。** 返信・コードコメント・ドキュメントの 3 種類それぞれにドロップダウンをひとつ、スコープはグローバルまたはプロジェクト単位（`.switchman/lang.json`）を選べます。設定しなくても構いません——最初に必要になった時点で、DSH の UI 言語で一度だけ尋ねて覚え、以後のすべてのセッションが自動で従います。

**5. 段階的検証：変えたら必ず確かめる。** 20 行を超える変更は tester による検証へ、300 行を超える変更やコア・セキュリティ・データ整合性のロジックに触れる変更は、さらに reviewer による独立レビューを重ねます。レビュー担当モデルは「この diff を書いたエージェント」が使ったモデルを基準に選び、可能な限りそれを避けます。プール内でどうしても避けられない場合は、結論に DOWNGRADED と明記されます。「チームを使うな」と一言言えば、即座に単独作業へ戻ります。

**6. `/vision`：テキスト専用モデルでも画像を扱える。** メインモデルが画像を読めないとき、DSH は入り口で画像付きメッセージをそのまま拒否します。画像を貼り付けて `/vision この画像のどこがおかしいか` と入力すれば、画像はファイルパスに解決されてマルチモーダルプールのモデルに読んでもらえ、結論は現在のセッションに戻ってきます。入力ボックスの上には「現在のモデルは画像を読み取れません」というヒントが先に表示されます。画像を直接送って拒否された場合は、自動的に `/vision` 形式に書き直して一度だけ再送するので、打ち直しは不要です。マルチモーダルプールが未設定の場合、コマンドは拒否して設定案内を示します。

モデルがひとつだけ？それでも入れる価値はあります——水位制御と段階的検証はモデルの数に依存せず、単一モデルの長時間セッションでも同じように恩恵を受けられます。

## 同梱スキル

- **db-query** — MySQL / Redis の読み取り専用検証：SQL を回してレコードを突き合わせ、キャッシュキー / TTL を確認し、ストア横断の整合性をチェックします。書き込みは一切拒否します。初回使用時に初期化が必要です（下記参照）。
- **git-commit-message** — 規範に沿った commit 文面を生成します。テキストだけを出力し、git の操作は一切代行しません。
- **requirement-docs** — 要件分析 / PRD / 設計ドキュメントの統一規範。成果物は `docs/requirements-and-design/` にアーカイブします。

## クイックスタート

1. **インストール** — 任意のセッションでエージェントに実行させるか、Web のプラグイン管理ページから：

   ```
   plugin_manager: install_bundle  target=dsh-switchman
   ```

   またはローカルチェックアウトから（link 方式。更新を取り込んだ後は `remove_bundle` + `install_bundle` で再インストール）：

   ```
   plugin_manager: install_bundle  target=/path/to/dsh-switchman
   ```

   またはターミナルから `dsh` コマンドでインストール——実行形態に合わせてプロファイルを選びます：

   ```bash
   dsh plugin --profile web add dsh-switchman      # Web GUI
   dsh plugin --profile desktop add dsh-switchman   # デスクトップアプリ
   ```

2. **DSH を再起動** — アプリを完全に終了してから開き直します（ページの再読み込みでは足りません）。クライアントモジュールのテーブルがこの bundle を認識できるようになります。

3. **言語設定** — 設定 → dsh-switchman、またはホームのサイドバーにある「Switchman ディスパッチセンター」。最初の画面でスコープを選びます：グローバル（この profile）またはプロジェクト単位（各プロジェクトの `.switchman/lang.json`）。次に 3 つのドロップダウンで、返信 / コメント / ドキュメントの言語をそれぞれ決めます。各項目の下には「現在: …」のステータス行が付きます。飛ばしても大丈夫——最初に使うときに一度だけ尋ねて記憶します（尋ねる言語は DSH の UI 言語に従います）。

   ![言語設定：スコープと 3 つの言語](docs/assets/conf-language-en.png)

4. **ディスパッチプールを設定** — 各プールカードで、プロバイダー別にグループ化された候補モデルにチェックを入れます。「手動順」にチェックすると、カードは番号付き優先リストに変わり、↑ ↓ × で順序を調整できます。各ルートの横では思考強度をピン留めできます（初期値は「レーンに従う」。ピン留めすると、そのモデルが実際に対応しているレベルが選べます）。上部のサマリー行は進捗をリアルタイムに反映します。たとえば「プール設定 6/6 · ランク付け 2 件 · モード アドバイス」。

   ![ディスパッチプール：軽量 / 機械 / 主力 / 高難度の 4 プール](docs/assets/conf-pool-1-en.png)

   マルチモーダルプールとレビュープールはその下にあります。さらに下には**能力ランキング**（6 プールで選んだモデルの和集合。番号が能力順、最強が先頭、S/A/B/C ティアでアンカー可能）と**実行モード**（アドバイス / 強制）があります。

   ![マルチモーダルプール・レビュープールと能力ランキング・実行モード](docs/assets/conf-pool-2-en.png)

5. **エージェントチーム** — 2 つのスイッチはデフォルトでオフ。まずは純粋な subagent モードで回します。自分でチームを組んでほしいときは「エージェントチームモード」を、二重の承認設定を省きたいときは「サブエージェントモデル許可リストの同期」をオンにします——スイッチの下に「N 件を同期済み + 同期時刻」のステータス行が出て、書き込み結果を確認できます。

   ![エージェントチーム：2 つのスイッチと許可リスト同期の状態](docs/assets/conf-team-en.png)

6. **コンテキスト水位** — 3 段階のしきい値（デフォルト 50000 / 90000 / 130000）、1 回あたりの読み取り予算、hard 段の挙動（制限付き通過 / 遮断）、自動ハンドオーバーのスイッチ、サブエージェントの独立上限、そのすべてがこのエリアにあります。最下部にはコマンドが 1 行：`/ctx-pause` 介入を一時停止 · `/ctx-resume` 再開 · `/ctx-handover` 即座にバックアップして引き継ぐ（セッションをアイドル境界へ誘導し、圧縮のリトライ期間を待つため、結果まで数分かかることがあります）。

   ![コンテキスト水位：しきい値・予算・コマンド](docs/assets/conf-ctx-en.png)

7. **確認** — セッションヘッダーに ⚡「自律チーム」バッジが現れます（隣の ◇ に現在のセッションモデルが表示されます）。またはモデルに直接「システムプロンプトの最後のセクションのタイトルは何ですか」と尋ねてみてください。dsh-switchman の規律に言及するはずです。

**db-query の初回セットアップ**（スクリプトの依存関係はスキルディレクトリ内に入るので、プロジェクトを汚しません）：

```bash
bash <install-dir>/skills/db-query/scripts/setup.sh
```

## 仕組み

- Host 側（`index.js` + `host/`）は、動的なシステムプロンプトセクション（言語 / レーン / 水位 / チーム）、読み取り予算と enforce の二重ゲート、4 つのスラッシュコマンド（ctx の 3 つ + `/vision`）を注入します。設定はすべて、保存した次のプロンプト組み立てから有効になり、再起動は不要です。
- Client 側（`client.js`）は設定ページ、セッションヘッダーの ⚡ バッジと ◇ モデル表示、ハンドオーバー進行中の動的表示を描画します。公式の settings-form サービス経由です。
- ホームのサイドバーにある「Switchman ディスパッチセンター」の入口は、クリック 1 回で同じ設定ページ（言語設定、ディスパッチプールとランキング、水位）を中央パネルとして開きます。元の設定入口もそのまま残ります。
- `cordis.patch.yml` は出荷時プリセットのプラグインリストを完全に保持し、persona suffix だけを拡張します。Agent Teams ツール本体は出荷時の bundle から供給され、チームモードをオンにすると自動で有効になります。

## メンテナンス

- DSH のアップグレード後に出荷時プリセットのプラグインリストが変わっていたら、新しい `presets/*.patch.yml` から `cordis.patch.yml` を再同期し（doctrine suffix は維持）、再インストールします。
- プロトコル行（`[SWITCHMAN:LANG|POOLS|WATERMARK|TEAMS]`）は意図的に英語・バイト安定を保っています——ローカライズしないでください。
- `npm pack --dry-run` は監査済みの 50 ファイル / ~205 kB の形を維持する必要があります（`docs/` のスクリーンショットはパッケージに入りません）。
