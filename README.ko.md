## 왜 필요한가

DSH 로 작업을 하다 보면 시간이 지날 때 두 가지에 부딪힙니다:

1. **세션이 갈수록 무거워집니다.** 히스토리가 컨텍스트를 수십만 token 까지 부풀리면, 모델은 건망증이 심해지고 느려지고 비용이 올라갑니다. 결국 수동 /compact 에 기댈 수밖에 없는데, 압축할 때마다 세부 사항이 떨어져 나갑니다.
2. **주력 모델이 모든 걸 스스로 처리합니다.** 파일 하나 조회하고, 테스트를 돌리고, 데이터를 대조하는 것까지 전부 주력 모델이 씹어 먹습니다 — 느린 데다 비용도 많이 드는데, 그 대부분은 사실 저렴한 모델에 맡겨야 할 작업입니다.

dsh-switchman 은 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)(DSH) 플러그인입니다. 설치하고 나면 기본 모델은 "모든 걸 자기가 처리"하던 방식에서 디스패처로 바뀝니다: 수위를 재고, 레인을 고르고, 작업을 나눠주고, 검수를 확인합니다. 새로운 모델이 아니라 DSH 에 얹는 조율 규율 한 세트와 설정 화면 하나입니다. 구체적으로는 일곱 가지를 합니다:

**1. 컨텍스트 수위: 긴 세션이 넘치지 않습니다.** 라운드마다 세션의 token 을 실시간으로 집계하고, 세 개의 수위선으로 단계적으로 강도를 높입니다: 50k(soft, 조정 가능)는 "이제 위임할 때"라고 알리고, 90k(hard)는 1회 파일 읽기 예산을 줄이며 마무리로 유도하고, 130k(force)는 자동 인계 — 세션을 fork 해 기록을 남기고, 컨텍스트를 압축하고, 이어받을 세션을 깨웁니다. 작업은 끊기지 않습니다. 인계 순간에 아직 실행 중이던 백그라운드 서브에이전트도 사라지지 않습니다: id, 작업 설명, 리포트 경로가 모두 인계 문서에 기록되어, 이어받은 세션은 리포트를 어디서 회수할지 알며 같은 일을 이중으로 시키지 않습니다. 나간 각 서브에이전트에는 독립 하드 한도가 붙고, 한도에 도달하면 HANDOFF 요약을 남기고 퇴장합니다.

**2. 여섯 개 디스패치 풀: 일에 맞는 모델을 붙입니다.** 경량 풀(economy, 소량 반복 작업), 기계 풀(mechanical, 템플릿형 재작성), 주력 풀(main, 일상 코딩), 고난도 풀(hard, 어려운 추론과 대규모 리팩터링), 멀티모달 풀(vision, 이미지 읽기), 리뷰 풀(review, 독립 검증). 설정 페이지에서 후보에 체크하고 우선순위를 정하며(S/A/B/C 티어 앵커는 선택), 라우트마다 사고 강도를 고정할 수 있습니다 — 강도 드롭다운은 각 모델이 실제 지원하는 레벨에서 직접 나오는 것이지 범용 3단계가 아닙니다. 기본 모델의 프롬프트에는 매 라운드 `[SWITCHMAN:POOLS]` 추천 표가 붙고, 모델은 그 표대로 일을 배분합니다. 실행 모드는 세 가지: 끄기 / 조언 / 강제(강제 = 풀 밖 모델은 즉시 거부).

**3. Agent Teams 모드: 단독 작업에서 팀 운영으로.** 기본값은 꺼짐이며, 설치 직후에는 가벼운 subagent 디스패치입니다. 설정 페이지에는 독립적인 스위치 두 개가 있습니다:

- **에이전트 팀 모드** — 켜면 팀 규율(기본 위임 + 단계별 검증 + 공유 작업 보드 규율)이 주입되고, DSH 의 Agent Teams 가 자동으로 활성화됩니다: 기본 모델은 상주 팀원을 데려오고(`spawn_teammate`), 공유 작업 보드에 일을 올리고(`team_task_*`), 팀원과 메시지를 주고받습니다(`send_message`). 팀을 꾸릴 타이밍에는 명확한 규율이 있습니다: 병렬로 돌릴 수 있는 독립 서브태스크, 양이 많고 자기완결적인 작업, 기본 컨텍스트 수위가 이미 높을 때, 역할 분리가 필요할 때. 일회성 단발 조사는 여전히 subagent 로 갑니다. DSH 출하 정책은 "사용자가 지명하지 않으면 팀을 만들지 않음"이지만, 여기서는 "필요하면 쓴다"로 뒤집습니다. 스위치를 다시 끄면 팀 조항은 흔적 없이 사라지고, 실행 중인 세션에서 팀 도구를 빼앗는 일도 없습니다.
- **서브에이전트 모델 허용 목록 동기화** — DSH 에는 "Agent 가 서브에이전트 모델 선택을 허용"하는 승인 목록이 있습니다: 풀에서 골랐지만 승인되지 않은 라우트를 기본 모델이 지명 디스패치하면 거부됩니다(팀 모드에서는 추천 표와 설정 페이지가 이런 라우트에 ⚠ 를 표시). 이 스위치를 켜면 여섯 풀의 합집합이 통째로 그 목록에 기록됩니다 — 양쪽에 이중 설정할 필요가 없어지고, switchman 이 유일한 사실 원천이 되며, fork 디스패치 경로도 함께 편입됩니다. 허용 목록은 "새 세션" 시점의 스냅샷으로 적용되므로, 동기화는 그 이후에 열린 세션에만 반영됩니다.

세션 헤더에는 직관적인 피드백이 있습니다: ⚡ "자율 팀" 배지, ◇ 현재 세션의 실제 모델. 자동 인계가 진행되는 동안에는 "인계 진행 중 · 세션 백업 / 컨텍스트 압축 / 깨워서 계속" 실시간 안내가 나타납니다.

**4. 언어 기본 설정: 한 번 물어보고, 평생 기억합니다.** 답변·코드 주석·문서 세 종류에 각각 드롭다운 하나, 범위는 전역 또는 프로젝트별(`.switchman/lang.json`)에서 고를 수 있습니다. 설정하지 않아도 됩니다 — 처음 필요해졌을 때 DSH 화면 언어로 한 번 물어보고 기억한 뒤, 이후 모든 세션이 자동으로 따릅니다.

**5. 인터페이스 언어: 플러그인 자신도 당신의 말을 씁니다.** 설정 페이지 맨 위에 "인터페이스" 섹션이 새로 생기고 "인터페이스 언어" 드롭다운(설정 키 `uiLocale`)이 들어갑니다: 자동(기본값 — DeepSeek Harness 앱 언어를 따름) 또는 플러그인 UI 가 갖춘 언어 중 하나를 수동으로 선택(언어명은 항상 원어명 그대로, 번역하지 않음). 바뀌는 것은 이 플러그인 자신의 UI — 헤더 배지, 홈 패널, 설정 페이지 — 뿐이며 DSH 앱 언어는 그대로입니다. 고르는 순간 재시작 없이 바로 미리보기가 바뀌고, 저장하면 profile 별로 기억되며, 다음 시작 때 자동 복원되고, 어떤 실패든 앱 언어로 되돌아갑니다(사전은 모두 번들 안에 동봉, 내려받기 불필요).

**6. 단계별 검증: 고치면 반드시 확인합니다.** 20줄을 넘는 변경은 tester 검증으로 넘기고, 300줄을 넘거나 코어·보안·데이터 일관성 로직을 건드린 변경에는 reviewer 의 독립 리뷰를 한 겹 더 얹습니다. 리뷰 모델은 "이 diff 를 쓴 에이전트"가 쓰던 모델을 기준으로 골라 가급적 피합니다. 풀 안에서 어쩔 수 없이 피할 수 없을 때는 결론에 DOWNGRADED 로 선언합니다. "팀 쓰지 마" 한마디면 즉시 단독 작업으로 돌아갑니다.

**7. `/vision`: 텍스트 전용 모델도 이미지를 다룹니다.** 주력 모델이 이미지를 읽지 못하면 DSH 는 입구에서 이미지가 붙은 메시지를 바로 거부합니다. 이미지를 붙이고 `/vision 이 이미지 어디가 잘못됐나요` 를 입력하면, 이미지는 파일 경로로 해석되어 멀티모달 풀의 모델이 읽고 결론이 현재 세션으로 돌아옵니다. 입력창 위에는 "현재 모델은 이미지를 읽을 수 없습니다" 안내가 미리 뜹니다. 이미지를 바로 보냈다가 거부되면 `/vision` 형태로 자동으로 고쳐 한 번만 재전송하므로 다시 타이핑할 필요가 없습니다. 멀티모달 풀이 설정되지 않으면 명령은 거부하며 설정 안내를 보여줍니다.

모델이 하나뿐인가요? 그래도 설치할 가치가 있습니다 — 수위 제어와 단계별 검증은 모델 개수와 무관하므로, 단일 모델의 긴 세션도 똑같이 이득을 봅니다.

## 번들 스킬

- **db-query** — MySQL / Redis 읽기 전용 검증: SQL을 돌려 레코드를 대조하고, 캐시 키 / TTL 을 확인하며, 스토어 간 일관성을 검사합니다. 쓰기는 일절 거부합니다. 최초 사용 시 초기화가 필요합니다(아래 참조).
- **git-commit-message** — 규범에 맞는 commit 문구를 생성합니다. 텍스트만 내보내고 git 작업은 절대 대신하지 않습니다.
- **requirement-docs** — 요구사항 분석 / PRD / 설계 문서의 통일 규범. 산출물은 `docs/requirements-and-design/` 에 아카이브합니다.

## 빠른 시작

1. **설치** — 아무 세션에서나 에이전트에게 실행시키거나, 웹 플러그인 관리 페이지에서:

   ```
   plugin_manager: install_bundle  target=dsh-switchman
   ```

   또는 로컬 체크아웃에서(link 방식. 업데이트 반영 후 `remove_bundle` + `install_bundle` 로 재설치):

   ```
   plugin_manager: install_bundle  target=/path/to/dsh-switchman
   ```

   또는 터미널에서 `dsh` 명령으로 설치 — 실행 방식에 맞는 프로파일을 고르세요:

   ```bash
   dsh plugin --profile web add dsh-switchman      # Web GUI
   dsh plugin --profile desktop add dsh-switchman   # 데스크톱 앱
   ```

2. **DSH 재시작** — 앱을 완전히 종료한 뒤 다시 엽니다(페이지 새로고침으로는 부족). 클라이언트 모듈 테이블이 이 bundle 을 인식하게 됩니다.

3. **언어 기본 설정** — 설정 → dsh-switchman, 또는 홈 사이드바의 "Switchman 디스패치 센터". 첫 화면에서 범위를 고릅니다: 전역(이 profile) 또는 프로젝트별(각 프로젝트의 `.switchman/lang.json`). 그다음 드롭다운 세 개로 답변 / 주석 / 문서의 언어를 각각 정합니다. 각 항목 아래에는 "현재: …" 상태 줄이 붙습니다. 건너뛰어도 괜찮습니다 — 처음 사용할 때 한 번 물어보고 기억합니다(질문 언어는 DSH UI 언어를 따릅니다).

   ![언어 기본 설정: 범위와 세 가지 언어](docs/assets/conf-language-en.png)

4. **디스패치 풀 구성** — 각 풀 카드에서 공급자별로 묶인 후보 모델에 체크합니다. "수동 순서"에 체크하면 카드가 번호식 우선순위 목록으로 바뀌고, ↑ ↓ × 로 순서를 조정합니다. 라우트마다 사고 강도를 고정할 수도 있습니다(기본값은 "레인 따르기". 고정하면 해당 모델이 실제 지원하는 레벨이 선택지로 나옵니다). 상단 요약 줄은 진행 상황을 실시간으로 반영합니다. 예: "풀 구성 6/6 · 랭킹 2개 · 모드 조언".

   ![디스패치 풀: 경량 / 기계 / 주력 / 고난도 4개 풀](docs/assets/conf-pool-1-en.png)

   멀티모달 풀과 리뷰 풀은 그 아래에 있습니다. 더 아래로는 **능력 랭킹**(여섯 풀에서 선택한 모델의 합집합. 번호가 곧 능력 순서, 최강이 먼저, S/A/B/C 티어 앵커 가능)과 **실행 모드**(조언 / 강제)가 있습니다.

   ![멀티모달 풀·리뷰 풀과 능력 랭킹·실행 모드](docs/assets/conf-pool-2-en.png)

5. **에이전트 팀** — 두 스위치 모두 기본값은 꺼짐. 먼저 순수 subagent 모드로 돌려 보세요. 스스로 팀을 꾸리게 하려면 "에이전트 팀 모드"를, 양쪽 이중 승인을 없애려면 "서브에이전트 모델 허용 목록 동기화"를 켭니다 — 스위치 아래에 "N개 동기화됨 + 동기화 시각" 상태 줄이 나타나 기록 결과를 확인할 수 있습니다.

   ![에이전트 팀: 두 스위치와 허용 목록 동기화 상태](docs/assets/conf-team-en.png)

6. **컨텍스트 수위** — 3단계 임계값(기본값 50000 / 90000 / 130000), 1회 읽기 예산, hard 단계 동작(제한 허용 / 차단), 자동 인계 토글, 서브에이전트 독립 한도가 모두 이 영역에 있습니다. 맨 아래 한 줄의 명령: `/ctx-pause` 개입 일시 중지 · `/ctx-resume` 재개 · `/ctx-handover` 즉시 백업 후 인계(세션을 유휴 경계로 유도하고 컴팩션 재시도 창을 기다리므로 결과까지 몇 분 걸릴 수 있습니다).

   ![컨텍스트 수위: 임계값·예산·명령](docs/assets/conf-ctx-en.png)

7. **검증** — 세션 헤더에 ⚡ "자율 팀" 배지가 나타납니다(옆의 ◇ 에 현재 세션 모델이 표시됩니다). 또는 모델에게 직접 "시스템 프롬프트 마지막 섹션의 제목이 뭐예요?"라고 물어보세요. dsh-switchman 규율을 언급해야 합니다.

**db-query 최초 사용 초기화**(스크립트 의존성은 스킬 디렉터리 안에 설치되어 프로젝트를 오염시키지 않습니다):

```bash
bash <install-dir>/skills/db-query/scripts/setup.sh
```

## 동작 방식

- Host 쪽(`index.js` + `host/`)은 동적 시스템 프롬프트 섹션(언어 / 레인 / 수위 / 팀), 읽기 예산과 enforce 이중 게이트, 4개의 슬래시 명령(ctx 3개 + `/vision`)을 주입합니다. 설정은 모두 저장 후 다음 프롬프트 조립부터 적용되며 재시작이 필요 없습니다.
- Client 쪽(`client.js`)은 설정 페이지, 세션 헤더의 ⚡ 배지와 ◇ 모델 표시, 인계 진행 중 동적 안내를 렌더링합니다. 공식 settings-form 서비스를 통해 이루어집니다.
- 홈 사이드바의 "Switchman 디스패치 센터" 항목은 클릭 한 번으로 같은 설정 페이지(인터페이스 언어, 언어 기본 설정, 디스패치 풀과 랭킹, 수위)를 중앙 패널로 엽니다. 기존 설정 입구도 그대로 유지됩니다.
- `cordis.patch.yml` 은 출하 시 기본 프리셋의 플러그인 목록을 그대로 유지하고 persona suffix 만 확장합니다. Agent Teams 도구 본체는 출하 bundle 에서 오며, 팀 모드를 켜면 자동으로 활성화됩니다.

## 유지 보수

- DSH 업그레이드 후 출하 시 기본 프리셋 플러그인 목록이 바뀌었다면, 새 `presets/*.patch.yml` 에서 `cordis.patch.yml` 을 다시 동기화하고(doctrine suffix 유지), 재설치합니다.
- 프로토콜 줄(`[SWITCHMAN:LANG|POOLS|WATERMARK|TEAMS]`)은 의도적으로 영어·바이트 안정을 유지합니다 — 현지화하지 마십시오.
- `npm pack --dry-run` 은 감사된 43개 파일 / ~205 kB 형태를 유지해야 합니다(`docs/` 스크린샷은 패키지에 포함되지 않습니다).
